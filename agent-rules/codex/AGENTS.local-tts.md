# Narration (local TTS)

A local GPU text-to-speech service (MCP server `local-tts`, MOSS-TTS, 31 languages, 48 kHz stereo) is always available. When a task's deliverable needs spoken audio — narration or voice-over for a video, slide deck, demo or tutorial; reading teaching material, an article or a story aloud; podcast or audiobook-style audio; an audio preview of a script; 旁白、配音、朗讀 — generate it with `generate_speech` instead of leaving recording to the user. Skip it when only the script text is wanted or another TTS provider is requested.

- Tools: `generate_speech` (returns path, duration_seconds, sample_rate, channels, format, model, voice, or status `pending` with a job_id), `get_speech_job`, `list_voices`, `list_models`, `tts_status`. Without MCP, use the CLI with a bounded wait: `tts say -f script.txt -l zh -o /abs/path/narration.wav --json --timeout 45`; exit 3 means still running: run the returned `fetch_command` with `--timeout 45` added until it exits 0, and never rerun `tts say` for an existing job.
- Script: write for the ear. Short sentences; spell out ambiguous numbers, units, symbols and abbreviations as spoken; `[pause 1.0s]` for deliberate pauses; blank lines between paragraphs; a mispronounced Chinese word can be written as tone-numbered pinyin separated by spaces (`哪 zuo4 cheng2 shi4`), and rare or variant characters in their common form (徑流, not 逕流). Save the script next to the audio.
- Model and voice: omit `model`; always pass `language` (`zh`, `en`, `ja`, …). Without `voice` each call gets its own voice (one call tries to stay consistent), so whenever several clips or batches must sound like one narrator, pass the same `voice` from `list_voices` to every call. Registering the user's own reference recording (`{{LOCAL_TTS_ROOT}}/assets/voices/` + `{{LOCAL_TTS_ROOT}}/config/voices.yaml`, then `systemctl --user restart local-tts`) needs the user's approval.
- Output: an absolute `output_path` inside the task's project directory, following its layout (e.g. `assets/audio/`, else `audio/`), with descriptive names. `.wav` for editing and video, `.mp3` for sharing, `.flac` for lossless. Overwrite only when deliberately regenerating that file; on `output_exists` pick another name or ask.
- Granularity: one file per scene or slide when durations drive timing; one call for a continuous reading (the service splits long text). Per call: ≤ 20,000 characters, each `[pause]` ≤ 60 s, all pauses ≤ 600 s (`input_too_long` / `invalid_pause`); split longer text at paragraphs into batches with one fixed `voice` and join them. Make calls sequentially; there is one GPU.
- Long text and interruptions: on `pending`, call `get_speech_job` with the result's `next.arguments` (job_id, the original absolute `output_path`, `overwrite` if set) until `completed` (always pass the path; after an MCP restart the default location is outside the project); never resubmit text that is pending. An error carrying a `job_id` says how to recover in `recovery`: an interrupted call → `get_speech_job` with the arguments it gives; `job_status: "failed"` or `unknown_job` → fix the cause if any and call `generate_speech` again. Speed is about 0.6× real time plus up to ~20 s model load.
- Hand-off: time scenes with `duration_seconds` and check the final product with `ffprobe`. Narration onto video: `ffmpeg -i video.mp4 -i narration.wav -map 0:v -map 1:a -c:v copy -c:a aac -b:a 192k out.mp4`, with the video at least as long as the narration (`-shortest` cuts speech off). Report audio paths, durations and the voice used.
- A completed result with `warnings` means a segment stayed suspiciously short (a sentence may be missing): regenerate that file once with `overwrite: true`; if it persists, tell the user which file and passage.
- Errors are JSON `{"error": {"code", ...}}`: `server_unreachable` → `systemctl --user start local-tts`; `queue_full`/`results_full` → wait and retry; `unknown_voice`/`unknown_model` → choose from `available`; `segment_failed`/`segment_truncated` → rephrase or shorten that passage and submit again; `unknown_job` → the service restarted or the job expired, submit again; `gpu_out_of_memory` → check `tts_status`, `nvidia-smi` and the logs, then tell the user. Logs: `journalctl --user -u local-tts`.
